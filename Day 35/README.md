# Day 35 — Реальная задача

Веб-сервис и агент для **черновиков технического задания** на продуктовые фичи: от краткого описания и вложений до структурированного документа с разделами, источниками и правками в диалоге.

## Какую задачу решаем

В продуктовой разработке ТЗ часто собирают вручную: каркас из шаблона, выдержки из старых спецификаций, комментарии из `.doc`/`.pdf`, уточнения в чате. Это долго, легко потерять связь «требование → раздел» и сложно переиспользовать похожие документы.

**Цель Day 35** — сократить путь от «есть идея фичи и материалы» до **согласованного черновика ТЗ**, где автор остаётся в контуре решений (каркас, адаптация чужого ТЗ, замечания по разделам), а рутину берёт на себя агент.

## Как AI участвует в процессе

| Этап | Роль AI |
|------|---------|
| Бриф | Модель ведёт диалог, решает следующий шаг через инструмент `finish_turn` (вопрос, каркас, черновик, правка раздела). |
| Материалы | Инструменты извлекают текст из PDF/DOCX/DOC/MD, ищут похожие фрагменты в RAG по прошлым ТЗ, при необходимости читают подключённый git-репозиторий (только чтение). |
| Каркас | `suggest_skeleton` предлагает шаблон (короткое или полное ТЗ); автор утверждает или просит адаптировать найденное похожее ТЗ. |
| Черновик | Сильная модель генерирует JSON-документ: разделы, утверждения с привязкой к источникам (`requirements` / `answer` / `rag`) или вопросы, если фактуры не хватает. |
| Правки | Замечание по разделу → пересборка одного раздела; сервер проверяет схему и «заземление» цитат. |
| Контроль | Конечный автомат этапов (`brief` → `plan` → `approved` → `draft` → `validated` → `done`) не даёт выпустить черновик без утверждённого каркаса. |

Две модели (настраиваются в `.env`): **strong** — рассуждение и генерация, **cheap** — вспомогательные шаги. Интеграция через OpenAI-совместимый API (по умолчанию Cursor `https://api.cursor.com/v1`).

## Быстрый старт

```bash
cd "Day 35"
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# задайте LLM_STRONG_API_KEY и при необходимости LLM_CHEAP_API_KEY
uvicorn app.main:app --reload --port 8000
```

Откройте `http://127.0.0.1:8000`: профиль автора, описание фичи, загрузка файлов, чат с агентом и панель разделов.

Docker:

```bash
docker compose up --build
```

Тесты без ключей (мок LLM):

```bash
python -m unittest tests/test_service.py
```

## Секреты и данные

- `.env` в репозиторий **не попадает** — только `.env.example`.
- Каталог `data/` (сессии, загруженные файлы, SQLite) **локальный** и в git не коммитится.
- Не публикуйте реальные ТЗ, ключи API и внутренние документы заказчика.

## Структура

- `app/main.py` — FastAPI и статический UI
- `app/agent.py` — цикл инструментов и `finish_turn`
- `app/tools.py` — извлечение файлов, RAG, каркас, контекст репозитория
- `app/generate.py` — черновик и пересборка разделов
- `app/flow.py` — этапы сессии
- `tests/test_service.py` — сценарии API и агента
