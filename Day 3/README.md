# Day 3 — Сравнение способов промптинга

Node.js CLI, который решает одну и ту же логическую задачу четырьмя разными способами через [Cursor SDK](https://cursor.com/docs/sdk/typescript) и сравнивает ответы, точность и расход токенов.

## Задача

**Условие:** есть 25 лошадей. В каждом забеге могут участвовать до 5 лошадей. Нужно найти минимальное число забегов, чтобы определить **1, 2 и 3 место** среди всех лошадей.

**Эталонный ответ:** 8 забегов.

Скрипт не решает задачу «вручную» — он отправляет её в модель Cursor и сравнивает, насколько разные стратегии промптинга помогают получить правильный ответ.

## Требования

- Node.js 18+
- API-ключ Cursor ([Dashboard → Integrations](https://cursor.com/dashboard/integrations))
- Установленный Cursor CLI (для `CURSOR_RUNTIME=local`)

## Развёртывание

```bash
cd "Day 3"
npm install
cp .env.example .env
```

Открой `.env` и укажи свой ключ:

```env
CURSOR_API_KEY=cursor_your-key-here
CURSOR_MODEL=composer-2.5
CURSOR_RUNTIME=local
```

| Переменная | Описание |
|---|---|
| `CURSOR_API_KEY` | API-ключ Cursor |
| `CURSOR_MODEL` | Модель (по умолчанию `composer-2.5`) |
| `CURSOR_RUNTIME` | `local` — агент на вашей машине; `cloud` — облачный агент (нужен Storage mode в Cursor) |

## Команды

Каждый режим запускается **отдельной командой**. Результат сохраняется в `results/<mode>.json`.

```bash
# 1. Прямой промпт
npm start -- --mode direct

# 2. Пошаговое решение
npm start -- --mode step

# 3. Мета-промпт (сначала составляет промпт, потом решает)
npm start -- --mode meta

# 4. Три эксперта с голосованием
npm start -- --mode experts

# 5. Сравнение всех четырёх сохранённых результатов
npm start -- --compare
```

Свою формулировку задачи можно передать после флагов:

```bash
npm start -- --mode direct "Есть 25 лошадей..."
```

## Режимы

### `direct` — прямой промпт

Задача отправляется модели как есть, без дополнительных инструкций.

**Суть:** базовая линия. Показывает, что модель ответит «сходу», без подсказок по формату рассуждения.

### `step` — пошаговое решение

К задаче добавляется инструкция: «Решай пошагово».

**Суть:** chain-of-thought в простом виде. Модель должна явно пройти этапы рассуждения, что часто улучшает точность на логических задачах.

### `meta` — мета-промпт

Два последовательных запроса:

1. Модель **составляет промпт** для решения задачи (без самого решения).
2. Модель **решает задачу** по составленному промпту.

**Суть:** модель сама формулирует, как лучше задать задачу. Два вызова API, суммарный расход токенов выше, но промпт может оказаться точнее ручного.

### `experts` — команда экспертов

Три параллельных роли с разными system-промптами:

| Роль | Задача |
|---|---|
| **аналитик** | Разобрать условие, ограничения и порядок действий |
| **инженер** | Дать конкретную схему забегов и итоговое число |
| **критик** | Найти типичные ошибки в решениях и назвать свой итог |

Итоговый ответ — **голосование большинством** по извлечённым числам. Если голоса разошлись, режим помечается как «спор».

**Суть:** multi-agent подход без оркестратора — три «эксперта» независимо отвечают, результат агрегируется.

### `--compare` — сравнение

Читает сохранённые `results/direct.json`, `results/step.json`, `results/meta.json`, `results/experts.json` и выводит:

- извлечённые числа забегов по каждому режиму;
- расход токенов;
- совпали ли ответы;
- какой способ ближе к эталону (8);
- у какого режима больше/меньше всего токенов.

## Примечания

- Папка `results/` тоже в `.gitignore` — это локальные артефакты прогонов.
- Для `--compare` нужно сначала прогнать все четыре режима.
